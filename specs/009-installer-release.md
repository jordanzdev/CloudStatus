# 009: MSI installer, release pipeline, `--uninstall` and `--create-desktop-shortcut`

**Status:** Implemented

## Context

Until now CloudStatus is a portable exe. This spec adds what CursorLock ships: a per-user MSI built
with WiX 5, the two command-line arguments the MSI runs, and a release workflow that publishes the
MSI, the portable exe and their checksums when a version tag is pushed. Everything is copied from
CursorLock's `installer/`, `build.ps1`, `.github/workflows/release.yml` and
`tools/Get-ReleaseNotes.ps1`, with CloudStatus names, its own `UpgradeCode` and its own branding.

Spec 007 left one decision here: whether the MSI turns on *Start with Windows*. This draft keeps
CursorLock's behavior (it does not): the installer opens CloudStatus at the end, which shows
Settings, where the option is one click away.

## Goals

- Install, update and uninstall without administrator rights, in English or Spanish.
- Uninstalling leaves nothing behind: files, shortcuts, settings or the `Run` entry.
- A tag `vX.Y.Z` publishes a GitHub Release with notes from `CHANGELOG.md` and SHA-256 checksums.
- The installer and its arguments never touch the running app's budgets.

## Non-goals

- *Check for updates* (010). This spec records where the MSI installed the exe, which 010 needs.
- Code signing. Neither project has a certificate; SmartScreen may warn on first download.
- Per-machine installs, `winget`, Chocolatey or any other distribution channel.
- Publishing a release. The workflow is added and tested with a manual run; pushing the first tag is
  the maintainer's decision.
- Turning on *Start with Windows* from the installer (see Context).
- The rest of the README (Usage, Settings, Why it has no impact, etc.), completed with 010.

## Requirements

### Package

- **REQ-009-01** `installer/Package.wxs` MUST build a per-user MSI (`Scope="perUser"`) that installs
  `CloudStatus.exe` into `%LOCALAPPDATA%\Programs\CloudStatus` and a Start menu shortcut, with no
  elevation prompt.
- **REQ-009-02** It MUST have its own `UpgradeCode`, and `MajorUpgrade` with same-version upgrades
  allowed and the language ignored, so that any installed version is replaced. A downgrade MUST be
  refused with a message.
- **REQ-009-03** It MUST record the installed exe path in `HKCU\Software\CloudStatus\Install`, value
  `Executable`, as the component key path, as in CursorLock.
- **REQ-009-04** *Apps & features* MUST show CloudStatus by `jordanzdev`, with the app icon and no
  *Modify* button.
- **REQ-009-05** A running CloudStatus MUST be closed through the Restart Manager. The app already
  exits on `WM_ENDSESSION` (001).

### Pages and language

- **REQ-009-06** The pages MUST be CursorLock's (`Dialogs.wxs`, `Texts.wxs`): a first page to choose
  English or Spanish, progress, done, cancelled, failed, errors and files in use. Every text MUST
  exist in both languages.
- **REQ-009-07** The language page MUST preselect CloudStatus's own `Language` setting if there is
  one, otherwise Spanish for any Spanish Windows language, otherwise English. The chosen language
  MUST be written to `HKCU\Software\CloudStatus\Language` (1 Spanish, 2 English) only when the page
  was shown, so silent installs keep the user's setting.
- **REQ-009-08** The done page MUST offer *Create a desktop shortcut* (unchecked, hidden if one
  already exists) and *Open CloudStatus* (checked). Opening runs the exe with no arguments, so it
  shows Settings (007). With basic UI (`/passive`) the app is opened directly.
- **REQ-009-09** The page bitmaps MUST be generated by `tools/New-Branding.ps1`, with no HyperX or HP
  marks.

### Arguments

- **REQ-009-10** `CloudStatus.exe --uninstall` MUST remove, and only remove: the `Run` entry if it
  launches this exe, the desktop shortcut if it points to this exe, and `HKCU\Software\CloudStatus`.
  It MUST run before the single-instance check, show nothing and return 0 on success, 1 otherwise.
- **REQ-009-11** The MSI MUST run `--uninstall` on a real uninstall only, not on an upgrade, before
  the files are removed.
- **REQ-009-12** `CloudStatus.exe --create-desktop-shortcut` MUST create or refresh a desktop
  shortcut to this exe through `IShellLinkW`, show nothing and exit. The MSI runs it from the done
  page when the box is checked.
- **REQ-009-13** Neither argument MUST start the app, open the dongle or send anything to the
  headset.

### Build and release

- **REQ-009-14** `build.ps1 -Version x.y.z` MUST produce `artifacts/CloudStatus-x.y.z.msi`,
  `artifacts/CloudStatus-x.y.z-portable.exe` and `artifacts/SHA256SUMS.txt` with LF line endings,
  covering both files. Each MSI is built from scratch, so each gets its own `ProductCode`.
- **REQ-009-15** `.github/workflows/build.yml` MUST build the MSI too, check it, and install and
  uninstall it silently on the runner (see AC-009-05).
- **REQ-009-16** `.github/workflows/release.yml` MUST, on a `v*.*.*` tag, build everything and publish
  a GitHub Release with the three files. Its notes MUST be the version's `CHANGELOG.md` section plus a
  downloads table, written by `tools/Get-ReleaseNotes.ps1`; the release MUST fail if that section is
  missing or empty. A manual run MUST only build and upload a workflow artifact.
- **REQ-009-17** The README MUST gain *Installation*, *Building*, *Publishing a release* and *Registry*
  sections, as in CursorLock.

## Performance budget

| Metric | Effect | Verified by |
|---|---|---|
| Running app | Unchanged: the arguments run in their own short process and exit | AC-009-07 |
| Exe size | Grows with the shortcut code; CI keeps it under 1.5 MB | CI |
| Network | None in the app. Only the release workflow, on GitHub, talks to GitHub | Code review, CI |
| Forbidden APIs | None added: COM `IShellLinkW` and registry deletion only | CI |

## Acceptance criteria

- **AC-009-01** `[auto]` Given `build.ps1 -Version 0.0.0`, then the MSI, the portable exe and
  `SHA256SUMS.txt` exist, the checksums match both files and use LF, and the exe is under 1.5 MB.
- **AC-009-02** `[auto]` Given a `CHANGELOG.md` with a `## [1.2.3]` section, when
  `Get-ReleaseNotes.ps1 -Version 1.2.3` runs, then the notes hold that section and the downloads table.
- **AC-009-03** `[auto]` Given a version with no section, or an empty one, when the script runs, then
  it fails.
- **AC-009-04** `[auto]` Given a stored `Run` command, when deciding whether `--uninstall` removes it,
  then it does only if it launches this exe, with any arguments and in any letter case.
- **AC-009-05** `[auto]` Given the CI runner, when the MSI is installed with `/qn`, then the exe, the
  Start menu shortcut and the `Install` value exist; `--create-desktop-shortcut` creates the desktop
  shortcut; and after uninstalling with `/qn`, the folder, both shortcuts, the `Run` entry and
  `HKCU\Software\CloudStatus` are gone.
- **AC-009-06** `[auto]` Given the CI runner, when the MSI is installed twice with the same version,
  then the second replaces the first and only one entry exists in *Apps & features*.
- **AC-009-07** `[auto]` Given `--uninstall` and `--create-desktop-shortcut`, when each runs, then it
  exits by itself with code 0 and creates no window (smoke test).
- **AC-009-08** `[hw]` Given a normal install in Spanish and then in English, then every page is in
  the chosen language, no elevation prompt appears, and CloudStatus opens in that language with
  Settings shown.
- **AC-009-09** `[hw]` Given CloudStatus running with *Start with Windows* on, when a newer MSI is
  installed, then the app is closed and reopened, and the settings and the `Run` entry are kept.
- **AC-009-10** `[hw]` Given *Create a desktop shortcut* checked, then the shortcut appears and opens
  the app; after uninstalling from *Apps & features*, nothing remains in the folder, the Start menu,
  the desktop or the registry.
- **AC-009-11** `[hw]` Given an installed version, when an older MSI is run, then it refuses with the
  downgrade message.
- **AC-009-12** `[hw]` Given the release workflow run by hand, then it uploads the MSI, the portable
  exe and `SHA256SUMS.txt` as an artifact and publishes nothing.
- **AC-009-13** `[hw]` Given the README, then its *Installation*, *Building*, *Publishing a release*
  and *Registry* sections match what the MSI, `build.ps1` and the app actually do.
